ChessGuru data dictionary

Every table ChessGuru stores, and what each column means. For how the tables connect, see data_lineage.pdf. All tables live in one DuckDB file, <data folder>/chessguru.duckdb.

  • Data folder: ./data when run from source, or %LOCALAPPDATA%\ChessGuru in the Windows app.
  • Usernames are stored in lower case. Times are UTC.
  • "Your" and "the player" mean the chess.com user being analysed. Opponents' names are never stored in the database.
  • Win chance is 0–100, from the point of view of the side that is moving.

Bronze: raw files

<data folder>/bronze/<username>/<YYYY-MM>.json bronze

One file per player per month · Written by fetch · Read by check

Exactly what chess.com's Published-Data API sent: {"games": [...]}. Kept unchanged so every table can be rebuilt from it. These are the only files that contain opponents' usernames. The fields ChessGuru uses from each game are:

FieldTypeMeaning
url, uuidtextLink to the game, and chess.com's game ID.
pgntextThe moves, clock times and headers (including the opening URL).
time_control, time_classtexte.g. 180+2; one of bullet, blitz, rapid, daily.
end_time, ratedint, boolWhen the game ended (Unix seconds); whether it was rated.
rules, initial_setuptextUsed to skip variants and custom start positions.
white / blackobjectEach side's username, rating and result code.
ecotextchess.com's opening URL (used if the PGN has none).

Silver: cleaned tables

Written by Python (src/chessguru). If the shape of these tables changes, SCHEMA_VERSION in db.py is raised and they are rebuilt from bronze.

silver_games silver

One row per game, from the player's side · Key (username, game_uuid) · Written by parse · Read by analyse, dbt

ColumnTypeMeaning
usernameVARCHARThe player.
game_uuidVARCHARchess.com's game ID.
urlVARCHARLink to the game on chess.com.
end_timeTIMESTAMPTZWhen the game ended.
time_classVARCHARbullet, blitz, rapid or daily.
time_controlVARCHARchess.com's code, e.g. 600, 180+2, 1/86400 (daily).
base_secondsINTEGERStarting clock in seconds. Null for daily games.
increment_secondsINTEGERSeconds added after each move. Null for daily games.
ratedBOOLEANWhether the game was rated.
player_colourVARCHARwhite or black.
player_ratingINTEGERThe player's rating, as chess.com records it for this game.
player_resultVARCHARchess.com's result code for the player, e.g. win, resigned, timeout, agreed.
outcomeVARCHARwin, draw or loss.
end_reasonVARCHARHow the game ended, from the loser's code (e.g. checkmated, resigned, timeout), or the draw type.
eco_codeVARCHARECO opening code, e.g. C50. May be null.
opening_nameVARCHARe.g. Sicilian Defense Najdorf Variation. Null if unknown.
opening_familyVARCHARThe name up to its first "Defense", "Opening", "Game", etc., e.g. Sicilian Defense.
pliesINTEGERNumber of half-moves played.
parsed_atTIMESTAMPTZWhen this row was written.

silver_moves silver

One row per ply (half-move), both sides · Key (username, game_uuid, ply) · Written by parse · Read by analyse, dbt

ColumnTypeMeaning
username, game_uuidVARCHARThe game this move belongs to.
plyINTEGERHalf-move number, from 1.
move_numberINTEGERFull-move number, as written in chess notation (1. e4 e5 are both move 1).
colourVARCHARWho moved: white or black.
is_player_moveBOOLEANTrue if the player made this move.
sanVARCHARThe move in standard notation, e.g. Nf3.
uciVARCHARThe move as from-square and to-square, e.g. g1f3.
pieceVARCHARPiece moved: P, N, B, R, Q or K.
fen_beforeVARCHARThe position before the move (FEN).
clock_secondsDOUBLEThe mover's clock after the move. Null in daily games or if missing.
time_spent_secondsDOUBLEPrevious clock + increment − this clock. Null if unknown.

silver_move_evals silver

One row per ply in analysed games, both sides · Key (username, game_uuid, ply) · Written by analyse · Read by dbt

Every score is from the point of view of the side that made the move.

ColumnTypeMeaning
username, game_uuid, plymixedThe move this verdict is for.
phaseVARCHARopening, middlegame or endgame (see the guide for the rules).
cp_before, cp_afterINTEGERStockfish's score in centipawns before and after the move, capped at ±1000 (a forced mate counts as ±1000).
mate_before, mate_afterINTEGERMoves to a forced mate: positive if the mover is mating, negative if being mated. mate_after = 0 means this move gave checkmate. Null if no forced mate.
win_before, win_afterDOUBLEWin chance (0–100) before and after the move.
win_dropDOUBLEHow much the move lowered the win chance (0 or more).
cp_lossINTEGERHow many centipawns the move lost (0 or more).
accuracyDOUBLEMove accuracy, 0–100 (Lichess formula).
labelVARCHARbest, good, inaccuracy (drop 5+), mistake (10+) or blunder (15+).
best_move_uci, best_move_sanVARCHARStockfish's preferred move in the position before. Null if there wasn't one.
tagsVARCHAR[]Why the move went wrong: hanging_piece, missed_fork, missed_pin, missed_skewer, missed_mate, allowed_mate, missed_punish. Often empty.

silver_game_analysis silver

One row per analysed game · Key (username, game_uuid) · Written by analyse · Read by analyse (to skip done games), dbt

ColumnTypeMeaning
username, game_uuidVARCHARThe game.
engine_depthINTEGERStockfish depth used. A game is analysed again only if a greater depth is asked for.
player_accuracyDOUBLEThe player's accuracy for the game, 0–100.
analysed_atTIMESTAMPTZWhen the analysis was saved.

Housekeeping tables

quarantine housekeeping

One row per game (or month file) set aside · Written by check, parse · Read by Data health page

Each step replaces its own rows on every run, so this always shows the current problems.

ColumnTypeMeaning
usernameVARCHARThe player.
source_fileVARCHARThe month file (e.g. 2026-11.json), or silver for games rejected while parsing.
game_urlVARCHARThe game, if known. Null when a whole month file couldn't be read.
reasonVARCHARWhy, e.g. "duplicate game", "variant 'chess960' is not supported", "PGN could not be parsed".
quarantined_atTIMESTAMPTZWhen it was set aside.
stepVARCHARcheck or parse.

pipeline_runs housekeeping

One row per pipeline step run · Written by every step · Read by Data health page

ColumnTypeMeaning
run_idVARCHARRandom ID for this run.
stepVARCHARfetch, check, parse, analyse or build.
usernameVARCHARThe player (all for a build from the command line).
started_at, finished_atTIMESTAMPTZWhen the step started and ended.
statusVARCHARsucceeded or failed.
detailsJSONWhat the step did (e.g. games downloaded, analysed), or the error if it failed.

One row · Written by db.py when the database is opened

ColumnTypeMeaning
versionINTEGERThe silver table layout in use. If it doesn't match the code, silver is dropped and rebuilt from bronze.

dbt views (schemas staging and intermediate)

Rebuilt by every dbt build (files in dbt/models/). They are steps on the way to gold; the dashboard doesn't read them directly.

ViewBuilt fromWhat it adds
staging.stg_gamessilver_gamesThe columns gold needs; date_day (UTC date); score (1, 0.5 or 0); "Unknown" for missing openings.
staging.stg_movessilver_movesThe columns gold needs.
staging.stg_move_evalssilver_move_evalsmove_accuracy (renamed); is_bad_move (mistake or blunder).
staging.stg_game_analysissilver_game_analysisengine_accuracy (renamed).
intermediate.int_player_move_evalsstg_moves, stg_move_evals, stg_gamesThe player's own analysed moves, with the extra tag low_clock on bad moves made with under 10% of the starting clock.
intermediate.int_game_eval_statsint_player_move_evalsPer game: the player's blunders, mistakes, inaccuracies and highest win chance.

Gold: the tables the dashboard reads (schema gold)

Built and tested by dbt build. The dashboard opens them read-only (src/chessguru/app/data.py). *_key columns are md5 hashes of the columns that identify a row, used to join tables.

outcomeVARCHARwin, draw or loss.

Tests that guard this data

  • Before silver: the data contract and quality checks (quality/checks.py).
  • On every dbt build:
    • keys are unique and not null
    • facts join to real dimension rows
    • outcome, colour, time class, label and phase only take allowed values
    • every silver game reaches fact_game
    • scores and win chances are in range
    • every evaluation belongs to a move
  • In the Python tests: no opponent name appears anywhere in the database (tests/test_dbt.py).
